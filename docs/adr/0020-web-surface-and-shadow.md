# ADR 0020: apps/web に面と影を戻し、押下の手応えと本文コントラストを確保する

- 状態: 採用（2026-08-28）。[ADR 0019](0019-web-design-language-classical.md) の決定1のうち **「面の作り」「影」「角丸」の3点だけ**を撤回・置換する。ADR 0019 のその他の決定（明朝の見出し、行長 `--measure: 60em`、○/✕ の丸つけ、配色の継承、560px 単一ブレークポイント、スマホの上部追従バー＋下部固定アクションバー＋ボトムシート）は**維持する**
- 関連: [ADR 0019](0019-web-design-language-classical.md)（本ADRの部分撤回対象）、[ADR 0017](0017-test-strategy.md)（UI/UX はテスト対象外）

## 背景

ADR 0019 は「面を塗らず罫線と余白で構造を出す」「影は浮遊要素（ボトムシート・モーダル）だけに残す」「角丸は 2px / 4px まで落とす」と決めた。採用から2週間運用した結果、2つの問題が実測で確認された。

### 1. 押下の手応えを影で表現できない

状態変化のモーション層を入れた際（`--ease-out` / `:active` の沈み込み / 「確定」のキーフレーム群）、押下フィードバックの主要な手段である「影が浅くなって沈む」が使えなかった。**影は面の上にしか乗らないため、背景が `transparent` で罫線しか持たない部品には成立しない。**

代替として `scale` による沈み込みを入れたが、幅いっぱいの帯（`.button-primary` は `width: 100%` / `min-height: 52px`）では `0.988` 程度が上限で、それ以上縮めると「沈んだ」ではなく「ずれた」ように見える。表現の幅が構造的に狭い。

### 2. 本文コントラストが実際には WCAG AA を割っている

ADR 0019 は配色を継承する根拠として「accent/ok/ng が dataviz validator 検証済み（surface `#fafcfe`）」を挙げた。**しかしこの `#fafcfe` は、実際にはほとんど描画面になっていない。**

`.sheet { background: transparent }` であり、`var(--panel)` の実使用は `styles.css` 全体で2箇所（`.generation-wait .generation-bar` と `.confirm-dialog`）しかない。**アプリのほぼ全ての本文は `--bg: #eef2f6` の上に直接乗っている。**

実際の地での実測値（WCAG 2.1 相対輝度）:

| トークン | `#eef2f6`（実際の地） | `#fafcfe`（ADR 0019 の記載） | `#ffffff`（本ADR） |
|---|---:|---:|---:|
| `--ok` `#0e8570` | **4.05** ✗ | 4.43 ✗ | **4.56** ✓ |
| `--ng` `#c4484f` | **4.26** ✗ | 4.65 ✓ | **4.79** ✓ |
| `--ink-soft` `#64748b` | **4.23** ✗ | 4.63 ✓ | **4.76** ✓ |
| `--accent` `#2867a8` | 5.19 ✓ | 5.68 ✓ | 5.84 ✓ |
| `--ink` `#22303f` | 11.95 ✓ | 13.07 ✓ | 13.44 ✓ |

本文の AA 基準は 4.5:1。**3トークンが実際の描画面で基準を下回っている。**

- `--ink-soft` は二次テキスト全般（`.hint` / `.session-sub` / `.question-list-date` ほか）
- `--ok` / `--ng` は採点の ○/✕（`.option-mark` は 17px / weight 600 で、AA の「大字」条件—18.66px 以上の太字または 24px 以上—を満たさない）

面を白く塗ると3つとも同時に解消する。**配色を1つも変えずに済む**点が重要で、ADR 0019 が配色継承の理由とした「コントラストの再検証を避けられる」という利点は、面を白くする方向でこそ実際に成立する。

## 決定

### 1. 面を塗る

`--panel` を `#fafcfe` から `#ffffff` に上げ、**実際に面として使う**。地は `--bg: #eef2f6` のまま据え置き、白い面との対比で構造を出す。

### 2. 影を2段に留める

「机の上の紙が1〜2mm浮いている」までとし、立体的なUI部品にはしない。**明朝の見出しと同居させるための制約である。** 強い影とゴシック的な立体感は、残す予定の「読み物」の語彙と衝突する。

```css
--lift-1: 0 2px 3px -1.5px rgba(0, 20, 40, 0.06);   /* 静止した面 */
--lift-2: 0 2.5px 6px -2px rgba(0, 20, 40, 0.08);   /* 選択・強調 */
--gloss:  inset 0 1px 0 0 rgba(255, 255, 255, 0.85); /* 上辺の起き上がり */
--press:  inset 0 1px 3px rgba(0, 20, 40, 0.09);     /* 押下 */
```

影の色を純黒にしないのは、地の `#eef2f6` が青灰だからである。純黒の影はこの地の上で濁る。

`--shadow-float`（ボトムシート・モーダル）は**据え置く**。浮遊要素と面の区別は残す。

### 3. 角丸を 6px / 10px にする

ADR 0019 の 2px / 4px から上げる。旧デザイン言語（10px / 14px）までは戻さない。影が乗る面に対して 2px は角が立ちすぎ、影の輪郭と角の対比が不自然になる。

### 4. 適用範囲

**押下フィードバックを持つ部品**（`--lift` + `--gloss`、押下時は `--press`）:
`.button`（`-primary` / `-ghost` / `-danger` / `-review` / `-answer` / `.review-unmark`）、`.option`、`.session-row`、`.session-delete`、`.review-summary`、`.mode-option`、`.result-grabber`

**面として立てる部品**（`--lift-1` または `--lift-2`）:
`.question-sheet`、`.result-sheet`、`.notice` / `.notice-error` / `.generation-error`、`.generation-stages`、`.generation-wait`、`.review-item`、`.session-item`

**凹ませる部品**（`--press` 相当の内側の影）:
`.select`、`.input`

**対象外**: `.tag` / `.cert-level-badge`（小さいピル。影を付けると密度が上がりすぎる）、`.skeleton-*`（ローディング表現）、`.score-meter`、`.masthead` / `.nav` / `.colophon`（構造の罫線だけで足りる）

### 5. 半端な適用を許さない

面と影は視覚言語そのものであり、**一部の部品だけに適用された状態が最も壊れて見える。** 上記の範囲は一度に適用し、画面単位・部品単位の段階的リリースはしない。

## 維持するもの

ADR 0019 の以下は変更しない。

| | 扱い |
|---|---|
| 配色（`--accent` / `--ok` / `--ng` / `--ink` / `--ink-soft`） | **1つも変えない**。面を白くすることでコントラストは全て改善する |
| 見出しの明朝（`--font-heading`） | 維持 |
| 本文の行長 `--measure: 60em`（`ch` ではない） | 維持 |
| ○/✕ の丸つけと 56px の判子（`.result-stamp`） | 維持 |
| 560px 単一ブレークポイント | 維持 |
| スマホの上部追従バー＋下部固定アクションバー＋ボトムシート、PC は中央1カラム | 維持 |
| 「デザインモックは仕様ではなく版面の参考である」（ADR 0019 決定3） | 維持 |

## 影響

- 変更は `apps/web/src/styles.css` に閉じる。`packages/shared` / `apps/api` / `apps/agent` / `infra` は触らない
- 新規依存はゼロ
- テストは追加しない（ADR 0017 により UI/UX はテスト対象外）
- 検証はローカル実機（PC の Chrome DevTools Protocol 実測＋スマホ実機）で行う。影と角丸は数値ではなく見え方で判断するため、静的解析では代替できない

## 却下した案

### プリセットUIキットの導入（shadcn/ui、daisyUI、MUI 等）

キットの価値の本体は既製の視覚言語（角丸・影・ゴシック体の階層）であり、それは ADR 0019 が残す部分—明朝の見出し、行長 60em、丸つけのモチーフ—と正面から衝突する。キットを入れて視覚言語を捨てるなら ADR 0019 の全面撤回になり、本ADRの範囲を超える。また shadcn 系は Tailwind 前提で、トークン定義付きの手書き CSS 1970行を書き換えることになる。

### ヘッドレスUIキット（Radix Primitives、Base UI 等）の導入

見た目を自前のまま挙動とアクセシビリティだけ借りる案。ただし確認ダイアログのフォーカストラップ（`HomeView.tsx`）もボトムシートのドラッグ（`lib/sheetDrag.ts`）も既に自前で実装・動作しており、置き換えの見返りが薄い。今回の課題（押下の手応えとコントラスト）はどちらもキットが解決する種類の問題ではない。

### 影を4〜5段にして立体的なUIに寄せる

紙面の語彙を捨てる方向。明朝の見出しを残すかどうかの再検討まで必要になり、ADR 0019 の全面撤回と同じ規模になる。今回の2つの実測課題は2段で解決するため、範囲を広げる理由がない。
